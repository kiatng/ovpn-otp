# v0.4.3

## Fixed

- A connect that reaches the tunnel but cannot add the network routes now
  ends as a failure with the reason, instead of showing "Connected" while
  nothing behind the VPN is reachable. On Windows the reason says to run
  ovpn-otp as administrator (or to let the OpenVPN Interactive Service start
  OpenVPN); on Linux it points at the "Linux: let openvpn create the tunnel"
  README section. Before connecting from a shell that lacks the rights, a
  warning says so up front.
- The diagnostic report no longer masks `>STATE:` lines in the management
  transcript, which hid the numbers that made them worth reading.
- "Update and restart" now restarts: the new copy waits briefly for the old
  window to finish closing before it takes the single-instance lock, and
  the old window really exits instead of hiding to the tray. Leftover
  update folders are removed on the next start.
- The "server closed the connection during login" failure: root cause found.
  The saved profile carried the certificate of another user (kiat) while the
  login was vendor1, and the server resets the connection before TLS starts
  on that mismatch. With the vendor1 profile and the OpenVPN Interactive
  Service (or administrator rights), 0.4.2 connected successfully, routes
  included. The error message now says to select the profile downloaded for
  this user.

## New

- One window at a time: starting `ovpn-otp-gui` a second time shows the
  window that already runs and ends. (Two instances would fight over the
  routes and the tunnel.)
- On Windows, closing the window leaves ovpn-otp running in the notification
  area. Its tray menu has Show, Connect, Disconnect and Quit; only Quit ends
  the program. A session keeps running while the window is hidden, and the
  window comes back on its own when the server asks for a code.
- `ovpn-otp install` puts the programs where the system finds them: on
  Windows a per-user folder (%LOCALAPPDATA%\Programs\ovpn-otp), the CLI on
  the user PATH, a Start-menu entry that starts the window with
  administrator rights through a scheduled task (one UAC prompt during
  install, never again), and `ovpn-otp uninstall` takes it back. On Linux,
  the programs go to ~/.local/bin with a .desktop entry for the app launcher.
- `ovpn-otp connect --elevate` (Windows) runs the session in the elevated
  desktop window instead of the current shell, so scripts and AI agents can
  connect without an administrator terminal: it starts the window when it is
  not running (scheduled task, no prompt; otherwise one UAC prompt), hands
  over the code, and waits for the outcome. The login must be saved
  (`ovpn-otp login`); the password never passes through the calling shell.
- The Settings view no longer repeats the profile, which is chosen on
  Connect. The "openvpn program" row opens a file dialog to pick the program,
  with "use automatic" to go back to finding it.

## Upgrade notes

No settings file changes are needed. On Windows, run `ovpn-otp install` once
to get the Start-menu entry and the CLI on the PATH.
